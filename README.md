# X-Ray Lab

A **teaching simulation** that shows, step by step, how a computer detects bright, round spots in an X-ray image.

> ⚠️ This project does not diagnose disease. Our images are not from real patients; they are synthetic images generated by code.

- **Live demo:** https://x-raylab.netlify.app
- **Demo video:** https://drive.google.com/drive/folders/1OluP9t8zgLHcw9TdSPY-T429zg8MFHLU (if it does not open, contact us: 92hackaton@gmail.com)

## 1. What does it do?

| | |
|---|---|
| **Mechanism** | Compare each pixel with its surroundings to find bright, round spots |
| **Input** | Window size `R`, threshold `T`, spot brightness, noise level, image number |
| **Output** | Marked spots, a verdict image, a plain-language explanation for each region ("Why?") |

The result updates instantly every time a slider is moved.

## 2. How the algorithm works

1. **ROI**: find the two large dark regions inside the body (the lungs) and search only there.
2. **Smooth**: average each pixel over a 5×5 window to reduce noise.
3. **Average**: use a window of size `(2R+1)` to estimate the "normal level of the surroundings".
4. **Diff**: `smooth − average`. How much brighter is this pixel than its surroundings?
5. **Threshold**: if `diff > T` and the pixel is inside the ROI, it is a "candidate pixel".
6. **Blobs**: group candidate pixels that touch each other into one region (flood fill), then filter by size and shape:
   - `< 15` pixels → noise
   - length/width ratio `> 1.8` → rib or edge
   - `> 600` pixels or fill ratio `< 0.5` → not a spot
   - anything else → "suspicious spot"

Every "magic number" is named inside `CFG`.

**Why does changing the threshold change the result?** If `T` is too high, even real spots fall below the threshold and are *missed*. If `T` is too low, faint bumps also get through (*false alarms*), and a spot can merge with a rib into one long region and then be *rejected*.

## 3. Technologies used

- **JavaScript** (`core.js`, inside `index.html`): runs directly in the browser: sliders, animation.
- **Python + numpy** (`xray_core.py`): the same algorithm in the terminal. `xray_lab.py` runs it on an image file (needs Pillow); `test_xray.py` runs the tests.
- **No** external services or AI models were used. All computation is our own code.
- JavaScript and Python do not call each other. The test checks that both sides give the same results (using `run_js.js`).

## 4. Testing

```bash
python3 -m unittest -v
```

| Test | What it checks |
|---|---|
| 1 | Clear spots are found, with 0 false alarms |
| 2 | A healthy image produces no flags at all |
| 3 | A very weak spot is missed (an honest limit) |
| 4 | A fake rib streak is rejected |
| 5 | Threshold trade-off: `T` = 8 / 20 / 28 |
| 6 | JavaScript and Python agree on 12 runs (4 images × 3 thresholds): candidate pixels, blob count, position and size of every flagged spot |
| 7 | The 3 failure examples on the website are real |
| 8 | Stable across many seeds and noise levels |
| 9 | The algorithm inside `index.html` is exactly the tested `core.js` |
| 10 | A PNG file and a different image size also work |

**Result:** `Ran 10 tests ... OK` (Python 3 + numpy + Pillow + Node.js).

Run it on an image file: `python3 xray_lab.py image.png --window 14 --threshold 28` or `python3 xray_lab.py --demo 7`.

## 5. Limitations

- Tested only on synthetic images; **not verified on real X-rays**.
- It only looks at brightness and shape. Noise and ribs can imitate a spot.
- It does not find very weak (low-contrast) spots.
- It is designed only for round, bright spots; it does not recognize other shapes.
